# ARM 与 PL 公平测速

适用于处理器/加速器对照及性能结论复核，也可迁移到其他 CPU/加速器。先区分新试验和离线复算；本目录命令仅离线读 CSV，不连接板卡。

## 直接使用

从提交包根目录运行：

```text
python skill/arm-pl-benchmark/scripts/summarize.py --csv skill/evidence/raw_trials.csv --phase main --baseline arm_novec --candidate pl
```

替换 CSV 为自己的数据即可。CSV 列为 `phase,input,condition,round,duration_ns,output_sha256`，每行一次测量；其他列保留但忽略。duration_ns 必须为正整数；同一输入的输出摘要须一致。脚本检查摘要格式与一致性，不重新计算输出，不证明输入相同。退出码 0 为数据检查完成，2 为输入错误或摘要不一致。标准输出为 JSON，统计结果不是“工程通过”信号。

给智能体的可复制提示词见 [prompt.md](prompt.md)，采集计划见 [plan.md](plan.md)。结果来源见 [case.md](case.md)。

## 方法与判断

1. 固定输入、权重、图和量化语义；保存文件身份与实际输出，证明两条路径完成相同数值任务。
2. 记录 CPU 核数/亲和性/频率、PL 频率、governor、编译选项及后台显示/采集/DMA。明确准备、复制、配置、等待和输出提取是否计时。双方计时边界需可比。
3. 按任务成本设计预热和交错轮次。保留每次测量，不按结果剔除异常。同轮重复共享环境，不能当成跨设备独立样本。
4. 分别报告逐输入中位数、合并中位数之比和逐输入等权结果。本脚本的等权结果定义为“各输入中位耗时算术平均后的比值”，不是各输入加速比的均值。
5. 各层中位数之和不等于整网中位数；1000/ms 仅为当前边界的串行换算率，不是端到端 FPS。
6. 编译器允许自动向量化不等于生成 NEON。微内核速率换算整网时间是条件推算，不是整网实测。峰值需写清 MAC/operation 约定及各自时钟。

## 失效条件

输入/权重/输出语义不一致、计时边界不同或条件混合时停止比较。输出摘要不同先查正确性。脚本不检验时钟、测量独立性、摘要真实性，不估计置信区间；统计区间需要与估计量和分组设计匹配。

已验证：附带历史主试验 CSV 可离线复算，效果和限制见 case；新脚本的测试记录见提交包 evidence/validation.json。没有跨板或新上板验证。
