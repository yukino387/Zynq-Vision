# 排查清单

| 触发条件 | 定位/处理 | 观察来源与边界 |
|---|---|---|
| 流水化后通道组/tile 首像素错 | 导出最早错误层，比较上一组 scale；锁存本组参数再进像素循环；重查调度与完整黄金 | 本项目错误符合前组量化比例；锁存修正当时尚待上板，不能说已解决 |
| compute II=1，整层仍慢 | 区分输入/权重/MAC/输出，查 burst、loader II、端口、lane、实际 DATAFLOW start/done | 本项目 loader/输出/池化排查；II=1 不代表持续无空泡 |
| 池化计算少耗时高 | 对照连续通道搬运与逐行短段，保持 signed/padding | 连续搬运有实测收益，不证明全部耗时是 DMA 启动 |
| 小 FIFO 额外 BRAM 很多 | 查绑定/深度，可试 SRL，重新查 LUT/布线/时序 | 本项目小 FIFO 默认绑定浪费 BRAM；SRL 也有成本 |
| HLS/实现资源不同 | 用 post-route，统一 BRAM 单位 | 诊断候选估计 213 DSP、实现 214 DSP |
| JTAG FT_Write/DAP | 核对连接/目标、单一控制者；确需电源重置说明原因，重载完整组合 | 下载大权重时观察；不把全部错误归因网线/模型 |
| UDP 无包、MAC 不解析 | 查 PS/PL 网口、IP、PHY 实际速率与 PS 配置、端口/收包计数 | 观察到千兆降百兆配置未同步；具体 PHY 依板卡 |
| 上位机控制争抢 | 用实际 socket/有效会话确认，不凭残留进程名要求退出；遵守 owner 协议 | 本项目会话归属，不是通用固定端口协议 |
| 工具退出 0 测试失败 | 查 Tcl catch、PASS/ERROR、错误数、黄金；传播非零失败 | XSDB 日志失败不能只看进程码 |
| PC 卡顿/构建停滞 | 不再启动重型构建；查自有进程、日志时间、内存、route overlaps；决定等待或停止本实验 | 本项目并行构建/拥塞观察，不随意杀全部 Vivado |
| 灰度预期整网少 2/3 | 分层算 MAC，后续通道由结构指定；分别测准备、首层、整网 | 不沿用旧模型形状估计新模型 |

以上是定位方向，只有新构建、时序与实测通过才能成为该工程结论。
