# 经验来源与证据等级

## 已实测

源工程 Zynq-7020，Vitis/Vivado 2026.1，裸机 PS 调度，INT8 灰度 224×224，125 MHz。案例数字不是跨板性能承诺。

2026-10-13 池化连续搬运：固定真实权重三次完整 forward 中位数 90.105 → 81.088 ms；三次池化合计 10.953 → 2.026 ms。同软件摄像头/预测/预览短测接收吞吐 10.868 → 12.006 FPS。实际 DSP 213 → 213，BRAM Tile 115 → 120，LUT 44737 → 43771，FF 60717 → 58163。

35 中间阶段、两个输出、padding/保护区匹配；三种实际池化尺寸的独立/原地写回共六项边界测试通过。约五秒端到端测，长期稳定性仍暂停。

证据路径相对源项目根目录，本包不复制模型/二进制：

- `temporary/pool_burst_test/build/comparison.json`、`comparison.csv`、`optimization_report.md`。
- `temporary/pool_burst_test/build/board/result.log`。
- `temporary/pool_burst_test/build/baseline_udp_results.json`、`short_udp_results.json`。
- 提交 `45d6ce0` 含 weight/requant/pool 优化及测试。上面的对照仅指池化子步骤，不能全归因 weight loader。

部分 build 证据不在 Git，竞赛交付需另整理原始数据与复现入口；仅本包不足以证明完整工程。

## 未通过候选

输出流水化早期诊断候选约 71.6 ms，但三次共 105 个阶段 hash 不匹配，不可发布。最早层通道组首像素符合上一组量化比例；已尝试显式锁存参数，本案例截取时尚待验证。说明正确性门槛优先，组/tile 边界需检查。

三模式诊断原型因布线拥塞取消，未上板，不构成性能结果。诊断候选 HLS/实际 DSP 不同，说明资源以最终实现为准。

## 协作过程摘要

下列是摘要，不是逐字聊天导出：

- 用户先限制 basic_op 适配，再逐级授权单层、Resblock、backbone 和顶层，由此形成逐级验证。
- 只分析时分离诊断和修改；计数器不便时采用 PS 计时/对照定位。
- 灰度只减少首层相关 MAC，不是整网少三分之二，必须核对真实层形状。
- 更快候选错误时保留正式基线，记录失败/修正，不以速度宣称成功。
- 用户曾要求避免重型并行，后授权综合/布局布线最多 16 线程；这是会话选择，不硬编码给所有队伍。

参赛仍需原始提示词、模型回答、自我纠错及版本对应；本摘要不能代替原始记录。其他队伍复用方法，不复用本地地址或未适配的性能数字。
