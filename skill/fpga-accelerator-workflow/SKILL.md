# FPGA 加速器实现与实测优化

目标：保留可运行基线，每次完成一项可核验的工程改进。其他模型和板卡可以复用方法，不能直接沿用本项目的地址、缓冲上限、权重格式或性能数字。

## 开始工作

确认实际仓库、Git 状态、构建/下载入口、工具版本和用户允许的修改范围。参考源码目录、生成 BSP 和实际开发目录可能不同。仅分析时不修改、不启动综合或下载。无必要时不整理目录、不新增抽象、不扩大为整网实现。

记录基线源码版本、bitstream/ELF/权重身份、运行时钟、输入尺寸、数据类型和测量条件；保留可恢复的硬件与软件组合。已有无关修改不纳入本次提交。

## 核心操作规则

1. 固定接口契约：驱动/寄存器、真实张量形状、CHW 等布局、padding、偏移、对齐、signed 类型、量化/舍入、激活和权重顺序。实际模型参数优先于文件名和历史假设。
2. 从最小算子向上验证，复用已验证模块。临时固件、诊断开关与测试放在独立目录，正式推理路径不残留调试协议。
3. 整数正确性优先。定位时检查中间阶段、tile/通道边界、padding 和保护区；CPU 参考实现相同数学语义，不能调用被测实现充当参考。
4. 用实际阶段计时和成对控制实验找瓶颈。compute II=1 不证明整层吞吐；关闭输出测到的通路仍含输入、权重和调度，不是纯 MAC。
5. 每个候选围绕明确假设修改，复用构建入口。曾出现卡顿的环境同时只运行一个重型厂商构建，线程数依据当前授权。检查日志和进程，避免重复启动；只停止明确属于本实验的进程。
6. 发布同时要求最终实现时序、实际资源、黄金输出与短时完整链路通过。功能失败的更快候选不能替换基线；诊断版本通过不代表移除诊断开关后的正式版本通过。

## 可复用校验脚本

`python scripts/verify_tensor.py --help` 查看用法。标准库脚本精确比对两个原始整数文件，核对元素数，报告 signed min/max、SHA-256、差异数量和首个差异；不匹配或长度错误返回非零状态。

```text
python scripts/verify_tensor.py --reference golden.bin --actual out.bin --dtype int8 --count 1617
```

先按接口契约导出无 padding 的逻辑张量。脚本不猜 CHW、不丢多余字节、不反量化或生成黄金参考；INT16 使用小端序。相同输出只证明这个输入一致，不能代替边界测试和长期稳定性验证。

## 汇报与保存

简述改动、验证阶段、基线/候选实测、资源/时序代价、未通过项目。实测、理论下界、估算分开；延迟、吞吐和端到端 FPS 分列，并注明采集/预览/通信是否开启。

用户要求保存 Git 时，只提交本任务源码、必要测试和构建入口，不顺带提交生成中间文件、权重、无关文档或其他人的修改。比赛材料整理、开源发布和许可证选择按另行授权执行。

## 使用边界

本方法在 Zynq-7020、Vitis/Vivado 2026.1、裸机 PS 调度、INT8/INT16 CNN 场景有项目经验。其他板卡、Linux/PYNQ 和量化方案需重新确认接口与实测。本技能不含已验证通用 PYNQ Overlay/DMA 实现，不承诺跨板性能或固定提升幅度。
