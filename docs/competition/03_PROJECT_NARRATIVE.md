# 阶段二修订：技术价值、优化历程与双应用叙事

修订日期：2026-10-25。作品定位：**基于Zynq-7020的FPGA加速智能视觉检测系统**。

本版替代此前“仅瓶盖主场景”的建议。牛奶盒缺陷与瓶盖检测共同构成应用验证，研发优化历程同样进入主线。用户已确认牛奶盒案例为**盒面贴片模拟缺陷**，不采用吸管候选，也不以液位检测替代。

事实基础：[01工程审计](01_ENGINEERING_AUDIT.md)、[02证据索引](02_EVIDENCE_INDEX.md)、新增[03A优化时间线](03A_OPTIMIZATION_TIMELINE.md)。E01～E40保留旧口径，E41～E52为定向补证。源码基准仍为 `5bcc771354f1fe061fc8297c5fed886473d2bbbc`；本轮未改源码、构建、上板或重测。这里只确定定位、取舍和内容预算；正式视频结构、逐镜头脚本、完整解说词继续暂停。

## 1. 定位结论

**围绕资源与真实瓶颈共同设计计算、访存和PS/PL流水，让早期低帧率视觉链路发展为可运行的INT8检测系统，再用牛奶盒贴片缺陷与瓶盖检测验证同一固定计算架构的应用复用。**

| 层次 | 评委应理解什么 | 表达重点 |
|---|---|---|
| 技术实现 | 神经网络算子在PL中怎样计算、怎样获得数据，PS怎样协作 | 计算结构、存储布局、分工与验证，是技术主体 |
| 工程演进 | 初期为什么慢，哪些选择有效，哪些因正确性/资源/时序退出，瓶颈如何转移 | 用原理解释状态变化，不念Git提交列表 |
| 应用验证 | 两个真实任务如何使用相同固定计算结构 | 实物、模型身份与原生输出对应，不堆功能 |

约1.7→约16FPS可以作为**裸机工程历程的两个状态**，不能作为同模型、同输入条件的纯硬件加速比。起点为416RGB/INT16旧模型，终点为224灰度/INT8模型；牛奶和瓶盖换型更晚，不能附赠当时16.6FPS成绩。[E45](02_EVIDENCE_INDEX.md#e45)、[E48](02_EVIDENCE_INDEX.md#e48)、[E50](02_EVIDENCE_INDEX.md#e50)

Web至多占应用段内约5秒，用于对应证据查询；本地记录足够时可省略。训练、移动端、MQTT、OTA和液位不扩成额外主线。[E03](02_EVIDENCE_INDEX.md#e03)、[E16](02_EVIDENCE_INDEX.md#e16)

## 3. 三个核心亮点及优先级

### 亮点一：计算结构与数据通路共同设计，让INT8产生收益

优先级最高。当前48输出通道×8输入通道结构，在一个空间位置/核坐标/输入通道组的有效发射迭代中执行384次INT8乘法。共同输入与两个打包权重相乘，修正高低半部符号；HLS计算子流水为192DSP、II=1。INT32部分和和INT64重定标保持舍入、负支路和饱和语义。[E07](02_EVIDENCE_INDEX.md#e07)～[E09](02_EVIDENCE_INDEX.md#e09)

供数采用64位字装8个INT8、行补齐、48×8权重重排、条件性的54KiB缓存及输入/权重A/B重叠。层间仍经共享DDR，不是全模型常驻片内或全网无等待。[E05](02_EVIDENCE_INDEX.md#e05)、[E10](02_EVIDENCE_INDEX.md#e10)

| 项目 | 叙事选择 |
|---|---|
| 重要性 | 直接说明加速器设计了什么，不仅是换用INT8名称 |
| 难度 | 有符号打包/归约、整数语义、bank带宽、补齐边界、读写布局一致及实现约束 |
| 演进依据 | 初期INT8正确计时约404.62ms，后续packed路径约241.443ms，重建48×8/布局后约104.69ms；是组合优化历史记载，不孤立归因给一项技术。[E48](02_EVIDENCE_INDEX.md#e48) |
| 视觉表达 | 一个DSP的双乘积→48×8通道图→64位字/权重块/A-B缓存，用一组简化数据块贯穿 |
| 证据 | 极短关键公式、HLS局部及对应实现报告，黄金对拍注明模型 |
| 边界 | 不说一拍完成整层、384完整卷积/周期、整网实测96GOPS；192是HLS子流水，217是特定终端全设计实现值 |

### 亮点二：用测量推动瓶颈转移，在完整链路中取舍

第二优先级，也是工程演进的核心。用三个因果问题组织研发历程：

1. **早期计算/访存慢。** 原416RGB/INT16、100MHz接收1.773FPS，共享核、连续读、互联/频率组合优化后2.971FPS，原数组可复算。不能将组合收益只归提频。[E45](02_EVIDENCE_INDEX.md#e45)、[E46](02_EVIDENCE_INDEX.md#e46)
2. **算子变快后，供数和串行空档突出。** 权重填充、重定标LUT、池化连续搬运、参数锁存/流式写回、成对输入及PS预处理/发送交叠，逐步推进同一INT8阶段。中间数字多依提交，重点讲机制和有限局部对照。[E31](02_EVIDENCE_INDEX.md#e31)、[E49](02_EVIDENCE_INDEX.md#e49)
3. **推理接近60ms后，采集节拍限制吞吐。** 相机根分频使帧期约66.6→33.3ms，不改Conv bitstream，历史裸机检测加预览短测约16.6FPS；30FPS是纯预览，原数组待补。[E50](02_EVIDENCE_INDEX.md#e50)

技术难度还在于知道何时退出：局部pointwise RTL周期少54.12%的候选，整机WNS却为-0.341ns；BRAM FIFO增加16个BRAM18K只换少量逻辑收益而放弃；PL自主sequencer也曾更慢。[E32](02_EVIDENCE_INDEX.md#e32)、[E51](02_EVIDENCE_INDEX.md#e51)

视觉上画“访存等待→A/B装载计算→PS准备下一帧→相机帧期”的时间条，再用一个失败候选经过时序/资源门槛解释取舍。每阶段标输入、精度和运行环境，跨条件断开，不画单调性能曲线。已作废101ms绝不使用，可用短提示说明先校正测时/黄金验证，再认定提升。[E48](02_EVIDENCE_INDEX.md#e48)

### 亮点三：固定计算架构复用到牛奶贴片和瓶盖检测

第三优先级，负责应用验证和系统完整性。RGB牛奶与RGB瓶盖包本轮解析的33×10命令一致，均6416360B；相对灰度模板只有首层输入通道变化。切换权重、bias/乘移参数、类别和规则，不需为兼容固定图重做PL。不代表任意CNN通用部署或同时双模型推理。[E19](02_EVIDENCE_INDEX.md#e19)、[E44](02_EVIDENCE_INDEX.md#e44)

PS逐条启动同一PL核执行33算子命令，其中21卷积，并承担预处理、解码、过滤、跟踪/规则；PL承担采集接入、算子及显示扫描。牛奶展示真实缺陷框，瓶盖展示目标/数量及适用过件记录，不硬套相同自动判定流程。[E04](02_EVIDENCE_INDEX.md#e04)、[E06](02_EVIDENCE_INDEX.md#e06)、[E11](02_EVIDENCE_INDEX.md#e11)～[E14](02_EVIDENCE_INDEX.md#e14)、[E43](02_EVIDENCE_INDEX.md#e43)

最佳视觉表达是同一板卡/相机/核结构保持，顺序切换模型，两段短实拍分别对应真值和原生输出。难点在包身份、类别/规则、预处理及帧/证据对应；模型与参考照不替代当前成功连续录像。[E41](02_EVIDENCE_INDEX.md#e41)～[E44](02_EVIDENCE_INDEX.md#e44)、[E52](02_EVIDENCE_INDEX.md#e52)

## 4. 双应用与液位边界

### 牛奶盒：盒面贴片模拟缺陷

影片明确标“贴片模拟缺陷”。参考照实际为饮料纸盒样件、白贴片、深背景，可说明模拟方法和取景，不是实机检测录像或工业真实缺陷分布。[E52](02_EVIDENCE_INDEX.md#e52)

| 模型/任务 | 已确认内容 | 使用原则 |
|---|---|---|
| milk-v15，2a25f824… | GRAY224、单defect槽，训练侧近似预处理/18照片旁证，说明未FPGA实跑 | 来源链，不将训练集指标写成板端准确率 |
| MILK-RGB-20261017，0f69bdf4… | RGB224、单缺陷；BOARD候选执行，62638us推理区间，无标注/准确率 | 明确缺陷模型板执行证据，贴片对应还须实拍 |
| MILK-RGB-v3，c046d903… | 有E23/E25运行/黄金记录；平台manifest仍列六钢材名 | 查清训练语义、槽位及贴片关系，不能仅凭版本名指定 |
| 吸管候选28e1c5df… | 有吸管/无吸管，较多漏检，说明不建议最终上板 | 本片排除 |
| 液位LEVEL系列 | 专用hash、ARM红标签与归一化行测量 | 独立任务，不替代外观缺陷，不占双应用名额 |

来源：[E15](02_EVIDENCE_INDEX.md#e15)、[E41](02_EVIDENCE_INDEX.md#e41)、[E42](02_EVIDENCE_INDEX.md#e42)。

单defect模型“没出框”不能区分好盒、空场和漏检；当前自动过件产品要求至少一个必需类别。不能把defect设为主体必需类后声称无缺陷盒正确自动合格。优先采用能确认实物存在的固定工位展示缺陷定位；人工检查/外部触发及记录以实际验收为准。本轮不加主体类、不改触发链。[E43](02_EVIDENCE_INDEX.md#e43)

### 瓶盖：检测和数量核验

CAPS-RGB-v1包2658b41a…、RGB224、cap一槽，展示实物数量、确认框和已配置规则。如用多帧过件，保留进场/观察/离场到记录对应。[E14](02_EVIDENCE_INDEX.md#e14)、[E34](02_EVIDENCE_INDEX.md#e34)、[E44](02_EVIDENCE_INDEX.md#e44)

本帧框数、beltCaps轨迹去重累计、过件记录数不同；未经真值核验的累计不作主指标，一组多枚产生一条记录不称一枚瓶盖。可人工移入移出真实演示，无需新造传送带，但不写自动产线分选或气密/旋紧缺陷检测。

### 顺序与换型

先牛奶贴片、后瓶盖：前者建立缺陷定位用途，后者展示容易人工核对的数量/记录。两者共同验证架构，不排斥任一，也不占据整片主体。

换型需停止、核对包和类别、匹配产品后再开始，无需完整播放下载/菜单。若两段实际采用不同运行时或bitstream，分别注明并缩小同一实际部署组合的主张。静态兼容已核对，现场切换和可靠演示仍待补。[E19](02_EVIDENCE_INDEX.md#e19)、[E44](02_EVIDENCE_INDEX.md#e44)
