# 第三阶段：三分钟参赛视频整体视觉设计与结构规划

日期：2026-10-25。作品：**基于Zynq-7020的FPGA加速智能视觉检测系统**。

本方案依据已审核的[03叙事定位](03_PROJECT_NARRATIVE.md)、[03A优化时间线](03A_OPTIMIZATION_TIMELINE.md)和[02证据索引](02_EVIDENCE_INDEX.md)。本轮只定向核对所选失败案例的已有对照文件，未重复工程审计。源码基准仍为`5bcc771354f1fe061fc8297c5fed886473d2bbbc`；没有构建、上板、录屏、拍摄或实际制作动画。

交付边界：这是导演策划方案，包含内容片段、画面调度、动画逻辑、素材状态和替代路径。P编号是内容片段，A编号是动画模块，均不是正式镜头清单；不提供完整逐句解说词，不进入05～07文件制作。

## 1. 总体创意：沿一帧图像观察这套系统

影片先给评委看到两种用途，再沿“实物图像→板端计算→检测输出”打开系统。计算结构从真实输入中引出，优化过程以等待、装载、计算和帧边界的运动关系表达；最后回到牛奶盒贴片和瓶盖的真实验证。贯穿画面的不是一个不断变大的FPS数字，而是**同一类图像数据如何被组织、处理和核对**。

核心叙事保持三个层次：

- 技术实现：双INT8打包、48×8通道并行、分块缓存/供数和PS/PL分工。
- 工程演进：计算和访存改进、整机约束、流水协作及采集瓶颈转移。
- 应用验证：牛奶盒**贴片模拟缺陷定位**与瓶盖**检测/数量核验**，顺序换模型，共用兼容的固定计算结构。

评委最终应能回答：PL实际计算什么；速度为何提升且为何不能把全部提升归给一项优化；为何局部更快的方案可能不能采用；两个应用输出分别证明什么。[E06](02_EVIDENCE_INDEX.md#e06)～[E11](02_EVIDENCE_INDEX.md#e11)、[E41](02_EVIDENCE_INDEX.md#e41)～[E51](02_EVIDENCE_INDEX.md#e51)

“沿一帧观察”是叙事方法，不表示摄像头像素不经DDR就流过全网，也不要求历史基准与当前应用使用同一帧。历史与应用段之间有明确的环境标识，不能以视觉连续性掩盖版本断点。

## 2. 视觉风格、信息层次与镜头语言

### 2.1 画面基调

推荐成片为16:9、1920×1080、30fps、逐行，主体174秒、6秒缓冲；174秒为5220帧，硬上限180秒为5400帧。这里是影片帧率，与推理FPS及HDMI扫描制式无关。

| 维度 | 设计选择 |
|---|---|
| 实拍 | 干净的真实实验台、固定光源、可辨认的板卡/相机/连线。保留少量手部操作，说明这是可运行原型；不借用工厂产线素材制造工业验证印象 |
| 技术动画 | 平面线条、块、网格、简洁时间条；正视图为主，只作少量平移/缩放。无需三维建模、芯片内部飞行或真实布线仿真 |
| 背景 | 实拍自然中性色；原理段深蓝灰背景与清楚留白，避免星空、电流墙、装饰性电路图 |
| 色彩语义 | PL计算为青色，PS控制/软件为琥珀色，DDR/缓冲为浅灰蓝；不通过/警示才用红。颜色之外始终有文字/形状标识 |
| 原生界面 | 保留实际检测框、标签和状态配色，不为统一美术改造产品UI、覆盖错误或重画检测框 |
| 动作 | 实物操作正常速度；数据块在因果关系发生时移动。转场约0.2～0.5秒，计入所在片段，不靠长片头/长黑场换气 |
| 工程截图 | 局部放大相关行/报告数字，来源仍可辨；原件归档。画面不出现整页代码滚动、终端瀑布流或快速闪过不可读报告 |

主信息三层：一个大结论或数字；一句机制/对象说明；一至两行必要条件/来源。普通画面最多一个新技术问题、两个突出数字。主标题约54～68px，机制说明约30～36px，条件/来源不小于26px；字幕约36px。来源标签与字幕留出不同位置，统一保留约5%安全边距。

这些是1080p制作参考，不是强制用小字容纳全部条件。条件放不下时删数字或拆解节奏，不能把关键限定藏成片尾注释。最终在正常速度、正常观看尺寸检查可读性。

### 2.2 保持视觉连贯的五个固定元素

1. **图像边框。** 实物取景/原生画面边缘，匹配转成原理图中的输入块；回到应用时恢复真实画面。演示用帧符号写`F[n]`并标“原理示意”，不得编造实际frame ID。
2. **数据方向。** 原理图中数据由左向右；控制命令由上向下；回写DDR画出返回路径。不能把共享DDR画成多个独立内存通道。
3. **固定PS/PL位置。** 同一简图反复使用，PS在上、PL在下、DDR居中；由局部放大进入计算，再缩回原位，减少重新读图。
4. **证据标识。** 历史裸机、原理示意、当前应用使用不同文字标签，不只用颜色区分。报告局部是证据插入，不另做PPT章节。
5. **实物回归。** 在64～70秒和98～104秒回到设备/当前证据核对，打断长技术段；不是为了证明性能而重复晃动板卡。

不以一秒一切制造信息密度。实物关键操作和读数留足时间，机制变化一次只出现一个。软件原生录屏可局部裁切，但不得裁掉影响结论的模型身份、异常或业务规则。

### 2.3 声音与节奏方向

音乐只作稳定节拍，解释和证据读数时降低密度。轻微点击/块交换声可辅助数据运动，不能给384路乘法逐个配音。实物拿放/操作保留适量同期声；没有音轨时画面也应能辨认任务与证据。此处不指定曲目或完整解说，不引入需额外授权的现成音视频资产。

## 4. 各片段的导演处理

### P01～P02：用途、设备与计算位置在同一空间建立

片头不做长logo动画。优先用真实手部/样件动作，让贴片位置、瓶盖数量和屏幕输出有可核对关系；标题在实物留白区域出现，不遮住对象。两个应用是不同次模型运行，不能合成左右同时运行的实时监控画面；可顺序剪接并分别显示模型标识。

P02从全景到器件局部，再叠一张三块简图。真实PCB只能用于辨认器件/连线；后期的数据线悬于画面旁并标原理示意，不沿板上走线伪装真实信号测量。PL块中只放“21卷积＋12其他算子”，上方PS写调度/预处理/判定；DDR在两者之间。显示扫描属于PL、界面绘制属于ARM。[E04](02_EVIDENCE_INDEX.md#e04)、[E06](02_EVIDENCE_INDEX.md#e06)、[E11](02_EVIDENCE_INDEX.md#e11)、[E12](02_EVIDENCE_INDEX.md#e12)

### P03：第一次性能变化只解释一个组合决策

采用两列有条件的历史状态，而不是趋势线：旧模型416RGB/INT16，左100MHz约1.77FPS，右142.857MHz约2.97FPS。用同一输入块、同一权重身份关系，展示连续读取、共享核和频率组合变更。大字只选这组FPS，原始538.326/311.175ms保留在报告附件，不与四个大数字抢注意力。

原JSON可制作一处相关字段的证据局部或依据原数组生成两列简图，注明“历史裸机｜两预测头＋预览完整接收”。不能说本片牛奶/瓶盖提高了这些倍数。结尾用短小但可读的阶段栏说明“后续256输入，再转224灰度INT8；输入/模型/精度改变”，取消连接线后进入当前计算原理。[E45](02_EVIDENCE_INDEX.md#e45)～[E48](02_EVIDENCE_INDEX.md#e48)

### P04～P08：从一个乘法器看到整个供数关系

P04/P05共用同一坐标与配色，避免变成两页独立图。P06回到真实器件后，P07把一组图像/权重字节带回同一PL框，P08再放大缓冲内部。贯穿的块表示数据关系，不代表这些可视块与某段实拍逐周期同步。

HLS报告仅在P05高亮192DSP/II=1等相关区域；完整报告留在证据包。P06不以拍摄DDR芯片证明带宽，P07不把四个HP或八个master画成八套独立DDR，P08不把输出缓冲画成不存在的跨空间块乒乓。[E05](02_EVIDENCE_INDEX.md#e05)、[E08](02_EVIDENCE_INDEX.md#e08)～[E10](02_EVIDENCE_INDEX.md#e10)

### P09～P10：一个具体失败说明工程取舍

选定**早期shared候选局部RTL更快、整机125MHz时序未通过**，不再展开第二个失败故事。数字来自[E51](02_EVIDENCE_INDEX.md#e51)的[原始对照](../../temporary/operator_pipeline_test/build/channels_comparison.json)：同一13×13、256输入/75输出、1×1用例的周期142938→65579，减少54.12%；独立AXI测试、无注入DDR停顿；该用例`errors=0`，完整系统125MHz WNS=-0.341ns。

屏幕主要显示“局部RTL周期 −54.1%”和“系统setup未通过｜−0.341ns”。数值正确性只标“该测试用例通过”，不能写全网黄金验证通过。资源采用“资源检查也是准入条件”的说明，不伪造资源失败或把另一个dual-bank放不下的7229/6664数字拼进此候选。

解释动作是：更短的周期条先推进，经过“用例正确性／资源／时序”检查时停在setup门前，保留基线，继续核验。此为**独立历史候选**，不能用箭头暗示它就是48×8 INT8版本，或随后被直接修成现存终端WNS+0.060ns。P10拍的是现在查看已有证据，不是重演当时故障；不摆拍示波器波形或虚构关键路径走向。[E32](02_EVIDENCE_INDEX.md#e32)、[E51](02_EVIDENCE_INDEX.md#e51)

### P11～P12：采集瓶颈转移与历史终点

从整机检查回到“帧与算子交接”，用时间条说明PS分段准备/通信与PL计算交叠，再突出相机根分频改变帧边界。PL时钟125MHz的标识保持不变，不让相机时钟改动看起来是Conv倍频。对比图的块长为原理示意，只有66.6/33.3ms明确引用历史记录，不从示意条推导额外端到端结果。

P12使用独立的历史证据画面，主要数字“约16.6 FPS”，条件栏贯穿8秒：

- 历史裸机短测记载；224灰度INT8、125MHz。
- 检测＋预览完整接收；原始采样待补。

不同时再显示30FPS预览、16.603、16.54或Linux15.21。原采样补齐后可更新证据等级，仍不能把它标成当前应用性能。转入P13前，清掉历史数字并显示“应用验证｜实际运行环境待确认”，确定拍摄配置后再填真实环境。[E49](02_EVIDENCE_INDEX.md#e49)、[E50](02_EVIDENCE_INDEX.md#e50)

### P13：贴片位置、模型类别与业务结论分开

建议22秒分为：约6秒实物/贴片定义，约10秒真实原生检测及对照，约6秒保持结果与身份可读。贴片/无贴片为分别采集的对照，不用擦除贴片、生成缺陷或后期移框。实物和录屏若组合，用实际对应的帧/时间记录关联，不把不同运行混作同时。

用语层次：样件真值为“有/无贴片”；模型类别为经确认的`defect/缺陷`等实际含义；输出为本帧检测框/分数。业务PASS/FAIL只有对应规则、目标存在和流程均验收后才能出现。无框默认只说明“本帧未检出缺陷目标”，不添加绿色“合格”动画。MILK-v3类别语义未核对前，不能仅靠后期把钢材标签改成“贴片缺陷”。[E41](02_EVIDENCE_INDEX.md#e41)～[E43](02_EVIDENCE_INDEX.md#e43)

### P14～P15：同核换型、数量与记录闭合

切换时短暂保留同一个核结构轮廓，仅替换模型/规则标识；实际停止、加载、匹配产品的过程可剪短，用“切换后”标识，不能假装无停顿并行切换。选择两个容易数清且已验收的数量，保留正常速度操作。

若自动过件通过，片段约6秒交代已知数量/规则，约10秒完整观察/离场和结果，约6秒对应记录/回收。观察时间超过预算时，先压缩规则介绍与查询操作；必要的时间省略须明示，不能加速物体运动来暗示产线速度。若只完成逐帧检测，整段改为真实数量输出对照，删除一件记录的承诺。

默认只突出本帧目标数和对应的一次观察/过件结果，`beltCaps`累计非主指标。一组多枚对应一条记录时屏幕文字写清单位；不得把该记录数称为瓶盖枚数。P15回到实物全景，同一板卡上的两个任务顺序展示，而非同时双模型。[E14](02_EVIDENCE_INDEX.md#e14)、[E19](02_EVIDENCE_INDEX.md#e19)、[E34](02_EVIDENCE_INDEX.md#e34)、[E44](02_EVIDENCE_INDEX.md#e44)

## 9. 拍摄与后期的实施约束

- 实物部分先固定模型身份与样件真值，再录设备/屏幕，避免先拍漂亮镜头再找结果配对。每次记录包短SHA、运行时、帧/记录关联；长SHA、原视频和采样留素材目录，不挤到画面中央。
- 设备摄影以固定机位、短距离平移和稳定近景为主。可使用普通相机/手机与稳定支撑，不要求微距探针、滑轨或3D模型。4K源仅为裁切便利，可选；1080p清晰源即可。
- 软件录屏尽量直接保存原生分辨率/帧率的清晰文件，再按成片规格编辑；不得用插帧补出新的检测状态、生成缺陷或替换真实标签。离散检测帧按实际节拍呈现。
- 拍显示器前做短曝光/条纹检查；清晰度不足用真实录屏插入，避免后期假屏。实拍样件应在已验证光照/视角内，不临时换成模型未见的高反光背景以追求科技感。
- 短运行演示和补测可以合并，不为影片重新综合历史候选；本轮不执行这些动作。需要新测试的项目按03/03A最小补证，失败与REVIEW原件保留。
- 数据标签优先级高于装饰。只能在有证据的版本范围内高亮“通过”；不能在其他段落闪过未解决的错误再在整体片尾泛化为长期稳定。
